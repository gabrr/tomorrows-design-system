## Integrated additions
POST /api/pricing/apply {project,node_id,provider,record_id} -> {project,record}; proposal only, preserve exact price units and USD currency. Config maps input_per_million to input_cost_per_million, output_per_million to output_cost_per_million, request_cost to cost_per_request. Metadata config.model (string), config.pricing_provenance (bounded string/object) and config.calibration (bounded string/object) are descriptive and accepted by validation. Generic cloud units without explicit hourly/token mappings cannot be applied automatically.
POST /api/calibration {project,measurements:[{node_id,source,samples_ms:[10 or more service-time samples],capacity_rps?:number,measured_at?:string}]} -> {proposal,calibration:[{node_id,source,service_mean_ms,holdout_mean_absolute_error_ms,...}],warnings:[]}; review before applying. Service samples exclude network/queue time; capacity must be explicitly measured, never inferred from latency. POST /api/observations/compare {result,observations:{metric:{value,absolute_tolerance}}} -> {checks,passed}. GET /api/runs and /api/runs/:id expose retained result evidence. UI system authority docs/UI-SYSTEM.md.

## Desktop conversational workspace (0.2.0)
The graph owns the desktop viewport (minimum target width 1100px). Float project/actions near edges, summon component/inspector/experiment/menu panels on demand, and show compact temporal playback after a run. `frontend/src/features/editor` owns the desktop canvas; workspace commands are in frontend/src/workspace/store.ts. Bundled browser assets are ES modules.

The existing AI endpoint receives the current project or a still-current pending draft and bounded earlier design conversation. Each proposal is validated and remains explicit until Apply to canvas or Apply & simulate. A generation token and workspace identity/revision fence reject superseded drafts and delayed replies after edits/replacement. No numeric form input is required: Codex chooses and explains illustrative defaults. Run telemetry is not included in AI prompts. Browser SpeechRecognition/webkitSpeechRecognition transcribes on explicit microphone click; it reports support, permission and service errors, stops on Escape/project replacement/page exit, preserves typed text, and never submits automatically. Physical microphone/service reliability is not established by mocked speech tests.

## Reversible exploration (0.3.0)
`frontend/src/domain/history.js` retains complete project snapshots in memory, capped at 50 edit steps and an estimated 8 MB. A single oversized current project is retained without undo snapshots. Dragging is recorded on release; rapid edits of one project-name field or node keyboard position are coalesced. A new edit after undo drops the abandoned future. Loading/importing/new-project resets history. Runs and pinned comparisons are evidence, not editable project state, and are not rewound. Undo/redo increases the workspace revision, so old AI/calibration/pricing reviews cannot regain validity. Native text undo remains available inside fields; app shortcuts apply outside text fields and native dialogs.

Results can pin a complete retained run as the comparison baseline. Future runs compare against that fixed result until released; the immediately previous run remains separately retained. JSON `_workspace.baseline_run` is optional under format version 1, validated against its own embedded project using the same result-integrity checks, and marked unverified external evidence on import. Baselines reset on project replacement. Graph node/edge/inspector telemetry is displayed only for a run from the current workspace revision; stale results remain readable with explicit labels and can be scrubbed separately. No history or telemetry is added to AI requests.

## Agent tools and shared architecture reviews
The optional WebMCP integration in frontend/src/automation registers native tools with runtime schemas, identity/revision guards, gesture/modal boundaries and explicit results. It calls actual Workspace commands, not DOM internals or a second state implementation. ArchitectureReviews.prepare validates a same-ID project with /api/validate, retains a fenced proposal and opens a visible review; apply/cancel are shared by UI and tools, and apply is one undo action. Unsupported registration leaves the UI usable. Agent activity is bounded metadata in memory. See WEBMCP-QA.md and features/experience-findings.md.

## Direct manipulation

The canvas has no persistent connect mode. Sibling input/output controls support click, keyboard and pointer wiring. Shift/Cmd/Ctrl selection, group move/duplicate/delete and shared-property batch edits use the same revision-fenced workspace commands as tools. Group duplication preserves internal edges while events stay on originals; group deletion removes attached edges and direct/condition-target events. Each compound edit is one undo step. Backend validation and stale-response guards remain mandatory for batch config changes. See features/direct-manipulation-check.md for observed and unverified interaction evidence.

Scenario event drafts are transient workspace state shared by experiment/events surfaces. Closing a panel retains them; page reload discards them as disclosed. Save revalidates both project revision and draft identity after backend validation, applies one undo action, then clears scratch state. Cancel/restart are explicit; project replacement clears drafts.

## Product refinement boundaries

The HTTP catalog also publishes `constraints:{node_config,edge,scenario,monthly}`, keyed by numeric field with `{min,max,integer}` from the actual Python validator. The UI uses these limits; unavailable metadata disables the affected numeric controls. Backend validation remains authoritative. Inline Astryx numeric drafts never commit an invalid value; its blur handling clamps ranges or restores invalid integer drafts.

`hasUnsavedWork()` includes changed scenario scratch events even when the project itself is saved. Both UI and native agent Save/Run reject such drafts until explicit scenario Save or Cancel. New/import/preset/open navigation warns before discarding them, and offers a return to the draft. Export still contains committed project state, not scratch events. New blank projects are pristine; replacements clear old panels, notices, selection, scratch, history and result state.

Forward connections keep their Bezier handles inside the actual horizontal gap. Canvas traffic labels are omitted when their estimated bounds overlap a component; selecting a connection exposes exact current-frame rate and cumulative routed count. These readings are hidden after a design revision, like all other current-graph telemetry.

## Product-review repairs (2026-11-12)

Published workspace snapshots are recursively frozen; commands clone before editing. Shared-property scratch values belong to the workspace rather than an inspector instance, remain visible after navigation, carry their originating selection/revision and require explicit Apply or Reset. Save, Run and proposal Apply reject unresolved group scratch; scenario scratch also blocks proposal Apply. Applying either draft validates against its original identity after asynchronous validation and creates one undo step.

AI conversation lifecycle is authoritative UI state, separate from generated explanation: ready to review, applied history or superseded. Applied history remains historical after later edits/Undo. Summary values derive from the actual before/after projects; full diff, JSON and advisory notes remain inspectable. Send/Apply dispatch through Astryx's urgent onClick handler with explicit request state; transition-wrapped clickAction must not defer immediate conversation/cancellation state behind external workspace updates. Close/Apply/Escape return focus to an appropriate composer control.

Library click insertion finds a vacant position and fits the unobscured canvas while leaving the library open. Directly positioned drops and explicit tool coordinates retain their meaning. Each pointer gesture has one owner; another pointer's release/cancel cannot finish it. Retained result tables use their submitted project and selected historical frame after edits; current-canvas telemetry remains suppressed. Imported evidence must contain costs, events and assumptions arrays before rendering.

Selection-based agent duplicate/remove require both expected workspace fence and expectedSelection, because human selection changes do not advance the project revision. Save results identify the submitted project/fence and whether that workspace remains current; completion never implies a replacement workspace was saved.

Group numeric edits use an Astryx text field with a retained raw workspace draft and a separately validated number. A complete valid value enables explicit Apply while the field remains focused; no blur or second click is required. Incomplete text remains recoverable across panel navigation and blocks Save/Run/proposal Apply. Decimal points and scientific notation are supported; range/integer limits come from the catalog and backend validation remains authoritative. The raw text and parsed value must agree before application, and asynchronous validation fences the exact draft identity. Ordinary immediate numeric fields retain NumberInput's commit-on-blur behavior. Closed hidden popover nodes do not suppress workspace keyboard shortcuts; visible menus/listboxes/dialogs retain keyboard ownership.

## Visible traffic and decision hierarchy (0.4.1)

Current canvas node arrivals and edge routed-call rates use cumulative counter differences over the actual adjacent retained-frame interval, including partial seconds. Arrivals include rejected calls; they are not successful completions or utilization. No prior interval or missing/reset counters means unavailable, distinct from zero. An edited workspace suppresses all current graph rates until rerun. Playback labels its sampled interval; Results labels the complete run. Opening Results fits the unobscured canvas once, never on replay ticks. Crowded edge labels may be omitted while node arrivals remain visible.

Proposal summaries expose concrete setting changes before affected-item inventory and Apply controls. Full before/after diff, proposal JSON and advisory notes remain available; status/freshness guards and explicit application semantics are unchanged. Summary grouping is structured, never inferred by parsing human labels.

Visible Astryx telemetry hints open on real card-button keyboard focus as well as hover. Escape goes to the visible tooltip through Astryx's layer stack before workspace actions. With no hint or active canvas gesture, Escape can dismiss the open panel. Runtime checks wait for focus ownership and queued hint closures to settle; they do not assume a fast Tab sequence instantly leaves one layer.
