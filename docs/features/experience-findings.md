## Required collaboration cycle

1. Two separate simulated-user specialists perform their named journeys on disposable data. A shared browser driver can execute their actions, but the report must say who drove it and who interpreted the evidence. Do not claim two agents independently operated a browser if only one did.
2. Research verifies platform/API constraints and traces each finding to evidence. UX and planner agree the target journey, architecture specialist reviews state/gesture/validation boundaries, and coordinator records the selected plan and owners.
3. Implementer receives exact file scope, acceptance IDs, context version and a bounded attempt. Keep source checks and visual evidence distinct.
4. QA reruns the failed journeys, normal UI alternatives, negative cases and representative visual checkpoints on the implementation revision. Findings reopen acceptance; code changes invalidate earlier sign-off.
5. Coordinator records accepted/rejected/blocked per ID and assigns concrete repairs for failures. Worker exit success, tool success and a green unit suite alone never satisfy the gate.
