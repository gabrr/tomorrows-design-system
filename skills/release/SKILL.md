# Release

Read milestone acceptance and run instructions at the candidate revision. Bound review to packaging, entrypoints, license/dependency declarations and executable evidence; ask the coordinator to assign missing ownership.

Verify python3 -m tds and python3 -m factory using the repository’s documented arguments. Exercise a clean local install/start, preset simulation, project save/reload, export/import and factory status without paid access. Test optional-provider absence and unavailable network as explicit states. Retain exact Python/platform, command outputs and remaining limitations in coordinator evidence.

Confirm repository skills validate, tests discover real cases and no credentials, private logs or runtime state enter release artifacts. Document which provider refreshes and model behaviors are implemented, unsupported or awaiting calibration. Do not translate a catalog listing into a fidelity claim.

Release readiness requires independent checks and integration evidence at the actual candidate revision, not only individual workers’ branches. Preserve failures and defer transparently; do not claim R6 complete with missing browser or recovery checks. No commit, publication, deployment or messaging unless the specific task authorizes it.
