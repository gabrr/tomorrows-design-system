# Skills Research

Read the assigned scope, plan/contract, relevant existing skill and docs/RESEARCH.md. Research only the decision at hand; fetch official publisher/provider documentation before treating a source as verified. Search snippets, remembered prices and failed fetches are not verification.

Record canonical URL, retrieval date, supported finding and proposed project consequence. Distinguish source fact from project inference, live endpoint test from documentation fetch, and implemented feature from proposal. Mark inaccessible sources unverified and preserve contradictory or missing evidence. Never claim current rates or measured accuracy from this document.

Keep each skills/name/SKILL.md scoped to its project task with name and description frontmatter, a bounded context set, concrete decision guidance and relevant primary links. Avoid copied manuals and duplicate contracts. Reuse fluid-design principles selectively: interruptible feedback, pointer adaptation, spatial continuity and reduced motion; they do not establish accessibility conformance.

Run the installed skill-creator scripts/quick_validate.py for every changed skill if PyYAML is available; report dependency absence rather than installing globally. Check links and behavioral usefulness separately because the validator only checks structure. Write acceptance rows as required check plus evidence/status; never count planned tests as passed. Only edit assigned skills and research/acceptance documents; no commits or native subagents.

Sources: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [OpenAI validation loop](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex). Authoring guidance adapted from the installed system skill-creator, not a fetched web standard.
