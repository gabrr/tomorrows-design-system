# Security reports

This project is in early development. Include the exact version or commit, operating system and a minimal reproduction in a report. Security fixes target the current development version; there is no maintained long-term support branch.

Use GitHub private vulnerability reporting from the repository's Security tab when available. If a private reporting channel is unavailable, open an issue requesting one without publishing exploit details, credentials, private architecture data or provider tokens. Do not include those details in public issues or launch-post comments.

The application is designed for a single user on loopback. Infrastructure experiments are simulated. AI proposals use a separately installed CLI and its configured provider access. Run the development factory only in a trusted local checkout with its documented sandbox, scope and review boundaries.
